# ADR 0001 — precise rates and explicit debt balance events

Accepted for implementation, 2026-10-16. Scope: local planning estimates, not lender accounting automation.

- Saved balance is the user-confirmed balance. Rendering, forecasts, month navigation and imports never accrue interest into it.
- Canonical annual rate is integer thousandths of one percent: `aprMilliPercent=6125` means exactly 6.125%. Unknown is null; 0 is known interest-free. Legacy `aprBasisPoints` becomes ×10 once in Dexie v4 and portable v1–v3 import; no balance changes. New exports are portable v4 and older apps cannot open them.
- `balanceAsOf` is a user-provided date or null. Old records migrate to null because updatedAt is not proof of a statement date. Payments advance this reference date; undo restores its previous value.
- Nominal monthly estimates use APR/12 with BigInt half-up once per period. Date-aware monthly accrual counts completed monthly anniversaries of balanceAsOf, clamps month-end dates and applies simple interest to the saved balance. Daily 365/360 are explicitly selected planning alternatives using actual elapsed days and a fixed denominator, rounded once. No lender grace-period, compounding or variable-rate assumptions are invented.
- Estimated present balance = saved balance + estimated unposted interest, clearly labeled. It never appears as posted/actual. Date estimates need rate, reference date and a nonnegative bounded period. Changing assumptions only changes estimates.
- Manual fees, purchases, refunds, interest posting and statement matching produce an ordered balance event: old/new balance, signed delta, effective date, recording timestamp, previous/new reference dates and note. No cash Ledger entry is implied by a balance adjustment.
- Each explicit monthly estimate posting uses a deterministic debt/month key. Refuse duplicate periods, including previously reversed postings. Refuse posting a full monthly estimate when a payment already records interest for that debt/month; use an actual statement reconciliation instead. Daily estimates are display-only in this version.
- Payments and balance adjustments share per-debt recording order. Undo only the latest unreversed balance event, with the saved-after-balance guard retained. Adjustment reversal retains the original event and adds reversedAt; payment Undo retains its existing remove-and-restore contract. A later statement adjustment must be reversed before an earlier payment can be undone. No blind addition of old principal onto a reconciled balance.
- Debt editor balance/reference-date changes are statement events too, so direct edits cannot bypass history. Rate/payment/name edits do not synthesize balance events. Existing payment idempotency and optimistic checks remain inside the atomic write.
- Backup v4 includes balance events and synthetic workspace metadata. Restore validates before one all-table write transaction. Settings downloads a user-initiated current snapshot before destructive replacement/clear, displays export age and warns for older snapshots. No recovery payloads in localStorage.
- Historical debt IDs in receipts/events may outlive deleted debts and obligation relinking. Validate invariant arithmetic and record shapes, not mutable current pairings. New posts require a real current debt and its expected timestamp.
- Fully unattended posting remains off and is not implemented. Portfolio snowball/avalanche comparisons, encrypted backups and income-frequency expansion remain separate future work.
